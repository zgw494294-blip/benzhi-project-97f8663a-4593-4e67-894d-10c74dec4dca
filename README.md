# 种子发芽势检验工作台

本项目面向种质库发芽检验员和种质质量复核员，围绕一个检验批次完成建档、草稿修订、方案冻结、整日分类观察、异常整改补测、观察封存、清单式技术复核和不可变报告归档。系统在页面中展示冻结工作量预览、累计发芽率、发芽势、重复组离散度、异常证据链、复核差异、状态时间线与归档摘要一致性。

项目采用单进程分层 Go 架构。浏览器页面和同源 JSON API 由同一个 HTTP 服务提供，不需要 Node 构建链。业务数据保存在本地 SQLite，启用 WAL、外键和启动完整性检查；所有写操作按事务串行提交，并使用批次递增 `revision` 拒绝陈旧页面写入。

## 构建

```bash
go build ./cmd/seed-vigor-web
```

## 运行

```bash
go run ./cmd/seed-vigor-web -addr=127.0.0.1:19081
```

浏览器访问 `http://127.0.0.1:19081/`。默认数据库为当前目录的 `seed-vigor.db`，可用 `-db` 指定其他位置。若未传 `-addr`，服务读取 `PORT`；`PORT` 只接受端口号并绑定 `127.0.0.1`。两者均未设置时默认监听 `127.0.0.1:19081`，显式 `-addr` 优先。

## 测试

运行全部测试：

```bash
go test ./...
```

运行有界 HTTP 冒烟自检：

```bash
go run ./cmd/seed-vigor-web -selfcheck -addr=127.0.0.1:19081
```

自检会在指定地址启动真实监听器，以临时 SQLite 数据库通过 HTTP 完成一条从建档到归档的正常流程，随后关闭服务并自行退出。

## 主要业务约束

- 草稿可由责任检验员携带 `expected_revision` 整体修订；就绪检查一次返回全部字段错误、样本重复错误、总粒数和观察单元数。冻结事务会再次执行同一领域检查，冻结后身份和关键培养参数不可改写。
- 同一检验批次号内不允许重复样本标识；所有写操作使用递增 `revision`，陈旧页面只收到当前 revision，不会覆盖新内容。
- 观察按日一次提交全部重复组。组覆盖、非负数、五类计数守恒和跨日分类演进在写入前统一校验，任一错误会回滚整日数据；较早日期的更正还会复验全部后续有效读数。
- 缺失读数、计数不守恒与组间离散度超限形成带目标日期和重复组的异常发生项。关闭必须同时具备原因、动作、异常打开后的目标范围证据和通过的规则复验；同一规则复发会生成新的发生序号并保留旧闭环。
- 观察窗口完整且没有未关闭异常时才能封存并进入复核。
- 复核员逐项审阅方案基线、原始读数、指标推导、异常闭环和操作轨迹。退回必须选择结构化整改范围，范围外写入被拒绝；重提会固化新增读数版本、异常状态和指标差异。清单全部通过、无开放异常且材料 revision 一致后才能批准归档。
